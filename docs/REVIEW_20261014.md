# 2026-10-14 功能审查与修复

审查覆盖原项目当前运行链路：启动与健康检查、公开行情、旧策略事件入口、新首板确认、信号日志/镜像、前向观察、全市场与涨停归档、名称解析、热点导入、旧收益页面和任务回调。未改变新版 Agent、实盘权限或私有策略仓库；不宣称历史训练与所有旧模块均已完成生产验证。

## 本次修复

- 信号入库统一上海时区及交易日期；界面将数据库时区转换为上海时间，避免晚 8 小时/跨日去重错误。不猜测改写旧数据库时间。
- 实际数据库时间列为不带时区类型，旧镜像会丢失时区信息：数据库连接明确设置上海时区，页面对可匹配本地日志的 SIGNAL_ONLY 信号采用日志原始时间纠正显示。没有本地原始时间的历史实盘记录不统一猜测加 8 小时。
- 拒绝 NaN、无穷价格/数量与无效信号方向，避免非法数据进入日志。
- 首板信号用决策时刻而非旧报价时刻记录；环境快照保存完整采集时间，不因同一分钟的字符串比较而引用触发之后的数据。
- 引擎构造完成后才发布单例，健康查询不再读到未初始化成员。
- 原策略初始化后的第一条 Tick 不再丢弃。行情覆盖不足后恢复时重置日内监听基线，避免跨长断档比较盘口；仍禁止实盘。
- 确认信号独立标记且从日志恢复；已确认候选不会因跌价或缺失行情变成“放弃”，历史页面以已有信号为准。缺失个股行情立即重置未确认计时。日线请求失败有一分钟冷却，避免饿死其他候选。
- PostgreSQL 镜像网络操作不持有全局本地 SQLite 锁；独立 SignalMirror 线程每 5 秒重试，策略回调只用本地名字缓存、提交日志，不等待数据库镜像。信号 API 合并本地记录与数据库记录，以 order_id 去重，未同步信号仍可见并带 mirror_pending 标识。数据库共享连接的查询用锁串行，连接超时 10 秒，查询超时 15 秒；数据库读取接口本身仍可能等待这些超时。
- 非交易时段明确数据当前未就绪，即使上次交易时段采集成功；历史采集时间仍保留。
- 热点文件按文件内日期命名选择，而非修改时间；默认超过 14 天不重新导入，避免启动重写旧名单。可通过导入参数 `max_age_days` 调整。股票池替换改为事务，失败回滚，冲突更新归类 hot，返回字段与调用方匹配。不会自动获取缺失的新热点文件。
- 旧收益页面移除 QMT 数据路径，使用公开不复权日线；只处理最近 50 条历史已执行记录，缺失买入日不推算日期，不把最高价视为可成交。全程亏损的最大收益不再错误显示 0。数据源不支持可靠均价，明确禁止该选项。
- 安装现有 requirements 声明但环境缺失的 croniter；回调数量测试覆盖现有 9 个回调。修正旧训练示例 UTF-8 源码误标 GBK，确保源码可编译。
