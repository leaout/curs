# 原项目仅信号运行设计

## 股票名称统一展示

`curs/stock_names.py` 为 JSON 接口中的标准股票代码补充 `stock_name`、`stock_label`。优先保留记录已有名称，缺失时从股票池、证券资料、当天完整市场名单及本地行情缓存解析；元数据缓存 120 秒。不在页面读取时逐只请求外部行情，无法解析时显示“名称暂缺”。信号表、候选列表、前向观察、持仓与收益图表使用名称；股票池和收益明细原有独立名称列保留。K 线图标题同时显示名称，原始代码字段仍用于查询与操作。

本地 SQLite `signals` 通过兼容迁移新增可空 `stock_name`，新信号保存名称并带入 PostgreSQL 镜像。历史记录通过接口解析名称，不重写交易记录或时间；名称可能为当前证券名称，并非已验证的历史名称。

## PostgreSQL 每日涨停归档

复用 `zt_stocks(trade_date, stock_code)`，增加可空 `snapshot JSONB`，不改原字段或删除旧数据。JSON 保存名称、连板高度、首次/最后封板时间、炸板次数、来源、记录时间、批次标识和预期总数。整批写入独立数据库连接事务，失败回滚，不产生部分完整快照；重复运行更新同日同代码，旧批次残留不进入新批次完整样本。读取校验批次数量，不接受残缺批次。

工作日 16:00 现有任务执行，采集代码拒绝 15:00 之前的快照，检查上游日期、代码唯一性和连续高度，失败重试三次再以非零码退出。空池不标为已确认“零涨停”，也不覆盖旧文件。数据库成功后再保存兼容文件。

情绪分析优先读取确切前一交易日的数据库记录，再尝试已验证本地档案与公开来源；不会用更早日期顶替昨日。旧表代码可展示收益与覆盖率，但连板高度为缺失，收盘完整性未确认，不据此进入综合情绪分类。历史缺失高度不能用今天上游数据回填。2026-10-12 现有 46 条记录无需删除或重建，等待今后盘后快照完善档案。

同次完整分页验证补齐 `302` 创业板代码识别与分类；真实接口返回的 5923 条名单已全部通过解析。覆盖率与数据新鲜度仍需独立验证，名单解析成功不等于行情齐全。

2026-10-13 修复：全市场证券识别及分市场统计包含 `689` 科创板证券，避免九号公司-WD 被拒绝导致完整名单采集失败。未知代码仍明确失败而非静默丢弃，以保持分页完整性；错误显示原始代码和市场。增加含 `689009` 的完整分页回归测试。

## 第三版全市场情绪观察（2026-10-10）

新增 `/market-sentiment` 与 `/api/market-sentiment`，由 `curs/market_sentiment.py` 独立后台线程采集，不复用热点池分母，不发交易事件，不改变已有买入条件。默认每轮完成后等待 120 秒，非精确同时刻快照；各股票都需在完成时仍满足新鲜度。交易时段及 15:05 前采集，周末不采集。法定休市日没有当日有效行情时降级，不声称已有完整交易日历。

证券名单来自东方财富沪深京 A 股分页接口，借鉴 AKShare 官方 `stock_zh_a_spot_em` 请求参数。校验总数范围、所有分页、唯一代码、支持的市场及证券名称。部分分页失败、重复页或总数变化时不发布名单；当日完整名单持久化缓存，不静默回退热点池或昨日名单。该名单不是正式上市/停牌状态主数据；证券名过滤只能作为保守规则，正式状态与上市日期待补。

行情使用独立腾讯五档批量客户端（2 个并发、每批 50），避免覆盖热点客户端缓存。每轮结束按股票时间戳检查当日、非未来、180 秒内；停牌、接口不返回、无有效涨跌停限制均计入缺失，不擅自从覆盖分母删除。默认整体及每个有证券的板块新鲜覆盖率都需达 90%。主板、创业板、科创板、北交所分开统计；ST/PT/退字名称包含在覆盖率内，但不进入普通情绪样本。

最近上海指数日线提供实际已有交易日期，选严格早于今天的最近日期查询东方财富该日收盘涨停池。涨停池要求日期匹配、非空、无疑似截断、代码唯一且包含 `lbc` 连板高度。成功后不可覆盖固定样本；缺失不能用更早涨停池冒充昨日。指数日线仅是交易日期代理，非正式未来交易日历；未取得该日期或连续高度时显示缺失。

统计：普通证券上涨比例、收益中位数、涨跌停数、累计成交额、触及涨停而当前未封比例；昨日涨停固定样本的收益中位数、低开比例、跌幅至少 5% 比例，以及按昨日高度分层的当前涨停晋级率。晋级以当时已观察成员为分母，同时展示完整固定样本数量；不把缺失当失败，不把盘中晋级当收盘晋级。日内 high 用于当日触板统计，而非信号之后的收益极值。

规则版本 `sentiment-v1`：覆盖完整且昨日样本覆盖完整后，需同一天最近三次连续有效快照、前两次不超过 10 分钟。上涨比例至少 60%、广度中位涨幅连续改善且昨日涨停溢价为正时标记“扩散观察”；连续恶化、昨日溢价负且至少 20% 观察成员跌幅达 5% 时标记“退潮风险观察”；其余为“分歧/中性观察”。只有一两个时点显示“待积累趋势”。失败中断不跳过，不越过午休形成连续趋势；阈值待前向验证，绝不直接标成已确认情绪主升或接力概率。

SQLite 表 `market_universe`、`market_cohorts`、`sentiment_snapshots` 保存名单、固定队列、每次判断和依据。API 保留历史快照，页面突出时间并明确不代表当前数据有效。线程运行与数据有效分开显示；来源故障、覆盖不足不会影响旧策略启动。

本版不实现题材自动归属、龙头排名、明日接力预测、实盘或模拟成交；后续基于可靠题材资料和累积前向样本建设。公开接口可能断连或限流，程序重试但不能保证可用性。验证命令：`.venv\Scripts\python.exe -m unittest test.test_market_sentiment test.test_first_board test.test_signal_observer test.test_public_signal_runtime -q`。

## 第二版首板快照确认

`curs/first_board.py` 由公开行情循环独立调用，不进入旧策略私有 Git 仓库。默认启用，异常不影响旧策略。只处理普通主板代码、约 10% 涨幅限制，排除名称含 ST/退字的证券。接近涨停价 1% 内进入日线检查：至少 6 根此前日线、最近一根不超过 10 个自然日、昨收一致且前日涨幅低于 9.5%。这是保守的首板筛选，不替代正式证券状态、完整交易日历或历史涨停数据库；调整价格不一致时暂停候选。

确认要求默认连续 60 秒最新价等于涨停价、至少 3 个不同时间样本、累计成交额增加，且至少 3 个其他观察标的涨幅达 3%。超过 15 秒断档、开板、同行条件消失或行情覆盖不足，重新计时。重复时间戳不会推进确认，午休断档不累计。每日内存清空，重启后重新确认；信号日志仍按日期、策略、代码、方向去重。

`market_data.first_board.groups` 可配置 `{板块名称: [600001.SH, 000001.SZ]}`；成员必须为标准代码且在当前新鲜观察池内才能计入。没有所属分组时退回观察池合力，页面明确标识不是题材板块；不会宣称发现龙头。参数只是待验证假设，不是盈利保证。每轮最多为一个新候选请求公开日线，避免批量阻塞；请求失败不生成信号。

状态保存在本地 `first_board_candidates` 表，页面展示日期、标的、原因和依据。信号名称 `first_board_confirmation`，100 股是固定观察单位，不是仓位建议；确认封板后可能根本无法买入。第一版价格跟踪自动覆盖新信号。未实现实盘、模拟成交、板块归属自动采集和实际持仓退出。测试增加断档、开板、数据不可用、前日涨停及重复确认覆盖。

## 第一版前向观察（2026-10-09）

新增 `/signal-review` 页面及 `/api/signal-review` 本地 SQLite 查询接口，不依赖 PostgreSQL 镜像成功。`/api/health` 的行情信息增加覆盖率、最近尝试/成功、连续失败次数、原因和交易时段。线程存活与数据就绪分别显示，非交易时段明确标注。

交易时段只处理当日新鲜快照。默认新鲜热点池覆盖率低于 80% 时不派发策略 Tick；`market_data.min_coverage` 可调整。重复时间戳可计入覆盖率，但不重复派发事件。观察对象包括热点池和最近 30 天买入信号的标的，后者只用于跟踪，不额外派发给原策略。

SQLite 新增 `market_observations`、`signal_context`、`signal_observations` 表：每分钟存环境，创建信号时保存最近两分钟内已有环境，按信号和日期保存后续实际采集到的最新价及极值。只用严格晚于触发时间的最新价；不能用当日 high/low 冒充信号后的最大波动。重复时间戳不会增加样本数，重启后保留历史。

本版环境仅为热点观察池的涨停、跌停、触板未封情况，不能代表全市场，不能判断完整市场情绪或板块合力；不启用环境择时过滤。数据缺失不补零，非交易日不合成价格，次日首个样本不冒充开盘，最后样本不冒充收盘。最大波动也是已观察样本极值，并非完整行情极值。暂不输出精确第 1/3/5 交易日收益，待交易日历与完整日行情接入后增加。实际成交登记、分层退出提醒和新首板策略留待下一版。

测试：`.venv\Scripts\python.exe -m unittest test.test_signal_observer test.test_public_signal_runtime -q`。

本项目与新版 Trading Agent 独立。原有策略继续运行，但不会模拟成交、创建持仓或向交易商发送订单。

## 数据与执行链路

腾讯公开五档快照 → 有效性、时间戳检查 → 原有事件总线 → 涨停策略 → SQLite 信号日志 → PostgreSQL 信号表 → `/signals` 页面。

股票池优先读取数据库 `hot` 池，回退到 `data/hotstocks.txt`。交易时段默认每 5 秒读取公开快照，拒绝超过 120 秒、未来、非当日和重复时间戳的数据。首次有效采集前刷新股票基础信息；单个策略异常不会中断其他监听器。公开接口没有服务保障，短暂盘口变化可能遗漏，不等价于 QMT 逐笔行情。

```yaml
signal_only: true
broker: signal
market_data:
  provider: tencent
  poll_interval_seconds: 5
  timeout_seconds: 8
  max_quote_age_seconds: 120
```

保持 `signal_only: true`，即使旧本地配置仍指定 QMT，也只创建禁止下单的 SignalAccount。Web 上实盘开关不代表信号监控开关；本模式不能启用实盘。

## 持久化

`data/strategy_records/signals.sqlite3` 是本地持久化日志，以交易日期、策略、证券代码和信号方向去重。记录包含原始信号时间、价格、数量和稳定订单标识。PostgreSQL 镜像状态为 `SIGNAL_ONLY`，不属于已成交订单；失败时每分钟重试。重启不会重复记录同日同策略同标的同方向信号。

仅在触发策略条件时记录信号，不保证每天有信号。没有真实持仓时，依赖持仓的卖出条件不会凭空产生卖出信号。

## 启动与定时任务

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_curs.ps1
# 管理员运行：更新已有任务，不创建缺失任务
powershell -ExecutionPolicy Bypass -File scripts/setup_schedule.ps1
```

| 任务 | 保留的触发时间 | 行为 |
| --- | --- | --- |
| CursBoot | 开机后延迟90秒 | SYSTEM 无需登录，隐藏启动，跨会话互斥防重复 |
| CursPreMarket | 周一至周五 08:50 | 仅重启本项目，不启动 QMT |

启动与盘前任务均使用 SYSTEM 服务账号，不保存用户密码；启用错过补跑，失败每2分钟重试，最多3次，执行超时10分钟。安装脚本只修改这两项任务，保留盘前触发时间，不修改盘后/导入任务。原任务 XML 自动保存到 `logs/task-backups/时间/`，可用任务计划程序导入恢复。项目、虚拟环境、数据库配置必须允许 SYSTEM 访问；用户专属凭据、映射盘与SSH密钥不自动继承。`logs/startup.log` 记录启动身份和时间。服务仍只记录信号；这不修复热点数据断更问题。
| CursAfterMarket | 周一至周五 16:00 | 采集东方财富公开涨停股列表，保存文件与数据库 |
| 每日导入任务 | 原有 21:00 | 保持原有数据导入，不改新版 Agent |

Web 地址 `http://127.0.0.1:5000`，健康检查 `/api/health`，信号页面 `/signals`。启动日志位于 `logs/curs.stdout.log` 和 `logs/curs.stderr.log`。非交易日空涨停列表不会覆盖已有名单；策略读取最近一个已有交易日的涨停记录，而不是简单减一天。
